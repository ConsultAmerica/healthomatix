# Healthomatix V2.0 — Enterprise AI Orchestration Implementation & Acceptance Report

**Version:** V2.0  
**Date:** 2026-10-29  
**Status:** Implemented locally (no commit / push / deploy). Production agent automation: **disabled** / Fake models only. Launch-state inherits V1.8 **NO-GO** for real PHI.

---

## 1. Executive summary

V2.0 adds a governed enterprise AI orchestration layer on top of the existing Healthomatix stack. Specialized agents are registered and versioned; runs are durable with enforced state transitions; tools execute only through a server-side gateway with role, tenant, and consent checks; high-risk outputs become immutable hashed proposals requiring human approval. Clinical and financial commits remain human-authorized. Brand, OIDC, tenancy, and V1.x clinical/billing/interop paths are preserved.

## 4. New AI orchestration architecture

```text
Request → AuthN/Z → create_agent_run (idempotent)
                 → execute_agent_run
                 → tool gateway (READ / PROPOSAL)
                 → structured output + usage meter
                 → waiting_approval (hash-bound)
                 → decide_approval → completed | rejected
```

## 6. Tool gateway

- **Forbidden autonomous tools** permanently blocked (`clinical.diagnose`, `clinical.prescribe`, `clinical.sign_note`, refunds, ledger edits, PHI disclose, etc.).
- **Read tools** re-authorize role + tenant + consent/patient scope server-side.
- **Proposal tools** create reviewable payloads; they do not commit clinical/financial truth.

## 7. Authorization model

- Platform registry/governance: platform admin only.
- Tenant runs/approvals: `tenant_admin` | `staff` | `provider` (endpoint-specific).
- Patient-scoped runs: active treatment consent required before context tools.
- Cross-tenant membership absence → 404.
- Agent-to-agent workflow steps each re-create runs and re-authorize tools (no permission expansion).

## 8. Human approval framework

Stored on `ai_agent_approvals`: proposal version, canonical SHA-256 hash, required role, expiry, one-time execution token. Hash mismatch → `PROPOSAL_INTEGRITY_FAILED` + safety event. Approve marks proposal executed for downstream human workflow — agent does **not** auto-sign notes or submit claims.

## 9. Clinical AI capabilities

- Clinical copilot run: authorized summary + verified/unverified observation separation + disclaimer.
- Medical scribe path: SOAP draft via Fake adapter `DraftBundle.content`; clinician remains signer.
- Pre-visit convenience: `POST .../encounters/{id}/ai/pre-visit-summary`.

## 10. Business AI capabilities

- Revenue cycle agent: claim-correction **proposals** for staff/admin.
- Clinic operations / scheduling proposals (medium risk).
- Support response proposals (no chart access for routine SaaS support tools).

## 11. Integration intelligence

- `integration.get_transaction_status` returns metadata only.
- `integration.propose_retry` requires approval; no autonomous high-impact replay.

## 12. Enterprise knowledge retrieval

- `POST .../knowledge/query` filters published articles by role visibility **before** returning text.
- Excerpt sanitization strips common injection phrases; response notes content is untrusted data.

## 13. Predictive operations

- `POST .../clinic/ai/operations-forecast` uses product-usage sample size.
- Refuses forecast when `sample_size < 5`.
- Returns high uncertainty + explicit “must not deny care / change triage” limitations.

## 14. Multi-agent workflows

- `POST .../ai/workflow-runs` with `clinical_previsit` orchestrates registered agents sequentially with independent authorization.

## 23. Known limitations

- Fake models only; no live PHI provider routing.
- Not all Phase-19 UI screens implemented.
- Forecasting is a deterministic naive baseline, not a trained model.
- Tenant AI budget hard-stops not fully wired to subscription entitlements.
- Background durable worker timeouts/retries are in-process state machine (no separate queue worker yet).
- Evaluation regression gates are recordable but not CI-blocking release automation.

## 24. Production-readiness gaps

1. V1.8 NO-GO for real PHI still applies.  
2. Do not enable production agent automation without executive approval.  
3. Require BAA-approved model routing before any clinical PHI LLM calls.  
4. Add CI gates for prompt-injection + authorization suites before agent version promote.  
5. Complete remaining doctor/patient engagement UI workspaces.  
6. Harden SQLite-vs-Postgres datetime awareness in all approval paths (mitigated for decide_approval).

## 25. Recommended V2.1 roadmap

1. Full quota/budget enforcement per tenant plan.  
2. Execution explorer + predictive ops + CS intelligence screens.  
3. Background job-backed timeouts, retries, circuit breakers.  
4. Expanded evaluation datasets and CI promotion gates.  
5. Additional multi-agent workflows (RCM denial, integration failure) with richer E2E.  
6. Optional approved-provider routing behind feature flags after security review.
