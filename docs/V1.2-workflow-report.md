# Healthomatix V1.2 — Patient & Doctor Dashboard Workflow Report

**Version:** V1.2  
**Date:** 2026-10-29  
**Status:** Implementation complete locally (no commit / push / deploy)

---

## 1. Executive summary

V1.2 connects patient and doctor dashboards to real, authorized application data while preserving V1.1 branding, auth, tenant isolation, and existing APIs. Patients get a coherent home for appointments, records, messages, care activities, and timeline. Doctors get a provider-scoped schedule, queue, and pending-task board. Unsupported clinical AI and durable notification inboxes are documented rather than fabricated.

## 3. Features completed

### Patient portal
- Dashboard sections: upcoming appointment, quick actions, recent records, messages, care activities, timeline
- Booking progress steps (clinic → provider → time → confirm)
- Appointment search; reschedule/cancel dialogs retained; Join Video Call removed from primary actions
- Records drag-and-drop upload, search/filter, preview drawer
- Messaging search + emergency-use notice
- Live “updates” chip derived from appointments/messages/profile (not a fake notification store)

### Doctor / clinic portal
- `/clinic/doctor` workspace: today’s schedule, searchable queue, pending tasks, quick actions
- Provider `scope=me` workboard filtering for providers; clinic-wide for admin/staff
- Patient chart workspace tabs: Overview, Appointments, Medical Records, Messages, Care Activities
- Extension tabs for Labs (live FHIR), Medications/Allergies/Notes/Care Plans (planned labels)
- Clinical workboard enriched appointment metadata

### Shared
- Brand tokens unchanged (`#047ADB`, `#089F7F`, `#042033`, …)
- Search limited to authorized API payloads already returned for the membership
- No new fabricated clinical events or AI medical responses

## 9. Security and authorization findings

- Doctor board uses membership role + workboard `scope=me` provider filter (not route-only privilege)
- Chart documents/observations remain consent-gated
- Patient searches operate on own authorized API results
- Clinic admin access to workboard does not imply unrestricted chart access; consent and patient routes still apply
- Messaging emergency disclaimer present on patient and clinic inboxes
- Outbox notifications are not exposed as PHI-bearing inbox previews

## 10. Known limitations

1. Appointment lifecycle statuses remain `booked` / `cancelled` only (no check-in / completed / no-show).
2. Clinic-side reschedule is not exposed; reschedule API is **patient-only**. Cancel is available to clinic roles.
3. Workboard “today” is UTC day, max 20 booked appointments; waiting queue is video session `scheduled`/`live`, not a front-desk arrival list.
4. Pending tasks = draft extractions + clinical drafts only (no generic care-task model).
5. No durable notification read/unread API; header chip is live-derived from live appointment/message/profile state. `notification_outbox` remains write-only.
6. Patient/clinic list search is mostly client-side on authorized payloads (patients list capped at 100); add server-side `q` + pagination next.
7. Video consultation CTA withheld pending product-ready visit UX (session APIs exist).
8. Medications, allergies, signed notes, and care plans are extension points only.
9. AI extraction remains verify-then-persist; no unverified results presented as clinical fact.
10. Messaging has no unread receipts.

## 11. Recommended V1.3 scope

1. Persisted notification preferences + tenant-aware inbox API (consume `notification_outbox`)
2. Appointment status machine (confirmed → checked in → in progress → completed / no-show) with migration
3. Clinic-side reschedule + server-side search/pagination for appointments, documents, patients, threads
4. Front-desk arrival queue distinct from video waiting sessions
5. Production visit/consult workspace with honest video readiness gates
6. Medications / allergies lists with consent scopes
7. Clinician-signed notes and care-plan / intake persistence
8. Optional AI pre-visit narrative with mandatory source citations and human approval
9. Message unread indicators and read receipts
