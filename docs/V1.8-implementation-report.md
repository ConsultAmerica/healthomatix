## 1. Executive summary

V1.8 audits the running Healthomatix codebase and hardens production-readiness controls without redesigning product workflows or brand. Delivered: security headers, rate limiting, health live/ready probes, platform-admin MFA gate hooks, malware scan fail-closed path, support tickets, launch-readiness API, CI security workflow, and a full documentation/evidence package. Formal launch decision: **NO-GO** for real PHI until critical residual risks close.

## 2. Existing functionality preserved

- Next.js + FastAPI + PostgreSQL/SQLAlchemy/Alembic stack
- Auth, tenancy, consent, clinical, telehealth, AI, RCM, FHIR/interop modules (V1.2–V1.7)
- Brand colors unchanged

## 3. Security improvements

| Control | Change |
|---|---|
| Security headers | `SecurityHeadersMiddleware` (nosniff, frame deny, referrer, permissions; HSTS in production) |
| Rate limiting | Process-local `RateLimitMiddleware` (configurable) |
| MFA | `REQUIRE_MFA_FOR_PLATFORM_ADMIN` + `amr`/`acr` enforcement on platform admin |
| Claims on request | Access token claims stored for MFA checks |
| Document screening | Fake malware port; reject marker; production fail-closed when required |
| Auth config | Exposes hardening / launch flags |
| Support PHI guard | Soft reject of clinical dump patterns in tickets |
