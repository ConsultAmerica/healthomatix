# Healthomatix V1.8 — Production Operations Runbook

**Date:** 2026-10-29  
**Environments:** development → testing/QA → staging → production (separation required; IaC not yet shipped)

## 1. Deployment

1. Merge reviewed PR; CI green (`.github/workflows/security-ci.yml`).
2. Deploy to staging; run smoke: `/api/v1/health/live`, `/api/v1/health/ready`, auth login, one tenant workflow.
3. Obtain release approval (Gate 6).
4. Apply Alembic migrations with backup confirmation (`alembic upgrade head`).
5. Deploy API + web; disable `DEMO_AUTH_SECRET` in production.
6. Post-deploy smoke + monitor error rates.

**Do not** auto-deploy to production without approved release policy.

## 2. Monitoring

- Health: `GET /api/v1/health/live` (liveness), `GET /api/v1/health/ready` (DB).
- Logs: request_id, method, path, status — **no** clinical text, tokens, payment secrets.
- Alerts (configure in ops tooling): 5xx spike, auth anomalies, DB down, queue backlog, backup failure, integration failures.

## 3. Incident response

| Severity | Example | Initial action |
|---|---|---|
| SEV-1 | Breach suspicion, total outage | Declare incident; contain; notify security owner |
| SEV-2 | Major degradation | Mitigate; communicate to tenants |
| SEV-3 | Limited feature outage | Ticket + fix |
| SEV-4 | Minor issue | Backlog |

Lifecycle: Detect → Classify → Assign → Contain → Recover → Validate → RCA → Corrective actions.

Response time targets are **organizational** — not invented here.

## 4. Backup & restore

- Strategy (required): encrypted DB backups, private object storage versioning, config backup, retention, access-restricted copies.
- RPO/RTO: **to be approved by organization** — do not invent contractual numbers.
- Restore drill: restore staging DB from backup; verify app boot + sample tenant read; record evidence.

## 5. Rollback

Triggers: SEV-1 regression, data corruption, security defect.  
Approver: release owner.  
Steps: redeploy prior artifact; if migration incompatible, use forward-fix plan (avoid destructive downgrade with PHI). Disable live integrations first if needed.

## 6. Support escalation

- Clinic UI: `/clinic/support` → `support_tickets` (no clinical dumps).
- Categories: patient, clinic_admin, provider, billing, technical, security.
- Security tickets escalate to security owner immediately.

## 7. Secret rotation

| Secret | Owner | Cadence | Emergency |
|---|---|---|---|
| SESSION_SECRET | Platform eng | 90 days | Immediate rotate signs out users |
| DEMO_AUTH_SECRET | Eng (non-prod) | On exposure | Remove; never prod |
| OIDC client secret | IdP admin | Per IdP policy | Revoke + rotate |
| DB credentials | Infra | 90 days | Rotate + recycle pools |
| Integration secrets | Integrations | Per vendor | Revoke connection |

Store production secrets in approved secret manager (gap until implemented).
